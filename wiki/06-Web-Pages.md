# Lesson 06 - Web pages

**In this lesson** Bookshelf gets its first experience for people: a catalog page (list, filter by author, add,
delete) and a page per book (read and edit). Both use the capabilities of lessons 04 and 05, in the two ways a page
can: the catalog from the browser with the **JS client**, the book page from the server with **`Route::page`**, and
its edit form with a small **controller**.

**Before you start:** lesson 05 is done (tag `lesson-05`): `capabilities` lists 6 capabilities, and
`docker compose ps` shows the 3 containers running.

**Time:** 60 to 75 minutes.

---

## New concepts

**View and Pug.** A **view** is the HTML of a page. Caligrafy writes views in **Pug**, files ending in `.pug` in
`application/views/`. Pug is a short way to write HTML: no closing tags, and the **indentation** says what is inside
what.

| Pug | HTML |
|---|---|
| `h2.cq-title Bookshelf` | `<h2 class="cq-title">Bookshelf</h2>` |
| `.cq-card` | `<div class="cq-card"></div>` (a `.` without a tag name is a `div`) |
| `input#title.form-control(type='text', name='title')` | `<input id="title" class="form-control" type="text" name="title">` |
| `h2= $book['title']` | the value of `$book['title']`, **escaped** (a `<` is shown as text, never run) |
| `p by #{$author['name']}` | text with a value inside, escaped |
| `each $a in $authors` / `if $errors` + indented lines | repeats the lines / shows them only when true |

The values are PHP. Indent with **spaces only**, 4 per level: a tab or one space too many breaks the page.

**Layout.** Every page starts with `extends ../default/master/layoutblocks`: the shared frame of the site (head,
stylesheets, the fixed header). The page fills the block `content`, and its scripts go in the block
`additional_scripts`. The layout gives each view `$home`, the address of the site (`http://localhost:8080/`):
build every link from it, `href="{$home}books"`.

**Page components.** Ready-made classes of `public/css/tokens.css` that give every page the Caligrafy look, with no
CSS to write ([page components](https://github.com/caligrafy/caligrafy-quill/wiki/7.-Views#pagecomponents)):

| Markup | What it is |
|---|---|
| `main.cq-page > .cq-card` | the page, then one centered white card below the header |
| `.cq-card-head > h2.cq-title + p.cq-note` | the title of the card and one line of context |
| `form.cq-form > .cq-fields.cq-fields--2 > div > label + input` | labeled fields, two columns on wide screens, one on phones |
| `button.btn.btn-primary.cq-submit` | the black button (at least 150px, on the left, like the sign-in screen) |
| `p.cq-error(role='alert')` | where the messages of a refusal go |
| `.cq-tabs`, `ul.cq-list > li.cq-item`, `p.cq-empty`, `.cq-section`, `.cq-foot` | tabs, list rows, the empty state, a block of text, the footer |

Several `.cq-card` in one page stack, one under the other. The pages of this course use one card each.

**Two ways a page uses a capability.**

| | In the browser: the JS client | On the server: `Route::page` with data |
|---|---|---|
| How | JavaScript calls `listBooks()`, `createBook(...)` | the route calls `get_book`, then renders the view with what it returned |
| Good for | interactive pages: add, filter, delete without reloading | pages that must work without JavaScript, and that search engines read |
| In Bookshelf | the catalog `/books` | the page of a book `/books/{id}` |

**JS client.** A JavaScript file, `public/js/capabilities.js`, generated by Caligrafer from your services: one
function per capability (`list_books` becomes `listBooks`). Each function calls `POST /capabilities/<name>` and
returns the `data`, or throws a `CapabilityError` with `status`, `code`, `message` and `fields`. In a page of the
application it sends the visitor's session and the CSRF token by itself. **Generate it again after every change to
a capability.**

**`Route::page`.** One line declares a page: `Route::page('/books', 'Bookshelf/books')` shows the view
`application/views/Bookshelf/books.pug`. Every page declared this way gets `$authorized` (is someone signed in?),
`$user` and the route variables (`{id}` becomes `$id`). With `data`, the page also gets what capabilities return:
`Route::page('/books/{id}', 'Bookshelf/book', ['data' => ['found' => 'get_book']])` calls `get_book` with the `{id}`
of the address, as the person who opens the page (the same checks as every other channel), and gives the view
`$found`. Only capabilities that change nothing (`readOnly`) can feed a page: opening a page never changes data. When
the capability refuses, the page does not render: a missing book answers **404**, with the view you name in
`notFound` (it gets `$message`, the capability's message), or the framework's error text without it.

**Pages never read the models.** The data of a page comes from capabilities, so the rules stay in one place: the
page, REST and AI agents all follow them.

**Controller.** A **controller** is a PHP class in `application/controllers/` whose methods (actions) answer
routes. You write one only when a page has **logic of its own**: here, the edit form, which saves, then either
redirects or shows the page again with the messages. A controller only calls capabilities:
`$this->call('update_book')` runs one as the visitor, with the route variables (`{id}`) and the posted form fields
as inputs (you can also pass them: `$this->call('list_authors', array())`), and returns the data or throws the
`ServiceError`.

**CSRF and PUT from a form.** A form changes data with POST. Caligrafy refuses a browser POST that does not carry
the CSRF token of the visitor's session (`[ERROR 3000] Security Error - Cross Site Forgery`, 403): it proves the
form came from your site. `=csrf()` writes that token as a hidden field. HTML forms only send GET and POST:
`=methodField('PUT')` adds a hidden field that makes Caligrafy treat the POST as a PUT, so `Route::put` answers it.

- The form, the tabs (`#authors`), the list (`#books`) and the empty state are empty boxes with an `id`: the script
  fills them.
- `script(type='module', ...)`: a JavaScript **module**, which may `import` other files.

**File `public/js/books.js`** (every action calls a capability through the JS client):

```js
// The catalog page: every action goes through the same capabilities as REST and AI agents
import { listBooks, listAuthors, createBook, deleteBook, CapabilityError } from './capabilities.js'

const form = document.getElementById('new-book')
const authorSelect = document.getElementById('book-author')
const tabs = document.getElementById('authors')
const list = document.getElementById('books')
const empty = document.getElementById('empty')
const errorBox = document.getElementById('error')
let authorId = ''   // the selected tab: '' for every author

// A refusal of a capability has a message per field (CapabilityError): show them under the form
function showError (e) {
  if (e instanceof CapabilityError) {
    errorBox.textContent = Object.keys(e.fields).length ? Object.values(e.fields).join(' ') : e.message
  } else {
    errorBox.textContent = 'Something went wrong. Try again.'
    console.error(e)
  }
}

function tab (label, id) {
  const b = document.createElement('button')
  b.type = 'button'
  b.setAttribute('role', 'tab')
  b.textContent = label
  b.className = id === authorId ? 'active' : ''
  b.setAttribute('aria-selected', String(id === authorId))
  b.addEventListener('click', () => { authorId = id; showAuthors(); showBooks() })
  return b
}

let authors = []
function showAuthors () {
  tabs.replaceChildren(tab('All', ''), ...authors.map((a) => tab(a.name, String(a.id))))
}

function row (book) {
  const li = document.createElement('li')
  li.className = 'cq-item'
  li.innerHTML = '<div class="cq-item-body"><p class="cq-item-title"><a></a></p><p class="cq-item-meta"></p></div><div class="cq-actions"></div>'
  const link = li.querySelector('a')
  link.href = 'books/' + book.id
  link.textContent = book.title
  li.querySelector('.cq-item-meta').textContent = book.author + ', ' + book.published_year

  const remove = document.createElement('button')
  remove.type = 'button'
  remove.className = 'btn btn-secondary'
  remove.textContent = 'Delete'
  remove.addEventListener('click', async () => {
    if (!confirm('Delete "' + book.title + '"?')) return
    try {
      await deleteBook({ id: book.id })
      await showBooks()
    } catch (e) {
      showError(e)
    }
  })
  li.querySelector('.cq-actions').append(remove)
  return li
}

async function showBooks () {
  const books = await listBooks(authorId ? { author_id: authorId } : {})
  list.replaceChildren(...books.map(row))
  empty.hidden = books.length > 0
}

form.addEventListener('submit', async (event) => {
  event.preventDefault()
  errorBox.textContent = ''
  try {
    await createBook(Object.fromEntries(new FormData(form)))
    form.reset()
    form.elements.title.focus()
    await showBooks()
  } catch (e) {
    showError(e)
  }
})

authors = await listAuthors()
authorSelect.replaceChildren(...authors.map((a) => new Option(a.name, a.id)))
showAuthors()
await showBooks()
```
- `import { listBooks, ... } from './capabilities.js'`: the functions of step 1.
- `createBook(Object.fromEntries(new FormData(form)))` sends the fields of the form, named like the inputs of
  create_book (`title`, `author_id`, `published_year`, `summary`).
- `showError()` shows the `fields` of a `CapabilityError` under the form: the messages of `$rules` and `handle()`.
- The rows are built with `textContent`, never by pasting a title into HTML: a title like `<b>` stays text.

### Step 3 - The routes of the pages

In `application/config/routing/web.php`, replace the first route (`Route::get('/', function() { return view('default/index'); });`) with:
```php
    Route::page('/', 'Bookshelf/books');
```
Then add these lines above `// MUST NOT BE REMOVED` and `Route::run();`:
```php
    // BOOKSHELF PAGES: the catalog (public/js/books.js) and the page of one book (data: get_book and list_authors)
    Route::page('/books', 'Bookshelf/books');
    Route::page('/books/{id}', 'Bookshelf/book', ['data' => ['found' => 'get_book', 'authors' => ['list_authors', []]], 'notFound' => 'Bookshelf/notfound']);
    Route::put('/books/{id}', 'Bookshelf\\BookController@update');   // the edit form: a page with logic of its own
```
`Route::page('/books', 'Bookshelf/books')` shows `application/views/Bookshelf/books.pug`. The page of a book (step 5)
gets two pieces of data: `found` from `get_book` (with the `{id}` of the address) and `authors` from `list_authors`
(with no inputs: `['list_authors', []]`). When `get_book` refuses, `notFound` shows the view `Bookshelf/notfound` (step 6)
with its message and status 404. The `PUT` route uses the controller of step 6. The full file is in the
checkpoint.

### Step 5 - The book page

The route of step 3 already gives the page its data. Write the view:

**File `application/views/Bookshelf/book.pug`** (one card: the book, then its edit form):

```pug
extends ../default/master/layoutblocks

//- One book, rendered on the server by Route::page with the data of get_book; the form calls update_book

block content
    //- $found: what get_book returned (Route::page data). After a refused save, the controller also gives $form and $errors
    - $book = $found['book'];
    - $author = $found['author'];
    - $form = isset($form) ? $form : $book;
    - $errors = isset($errors) ? $errors : array();

            .cq-section
                p= $book['summary'] ?: 'No summary yet.'

            form.cq-form(method='POST', action="{$home}books/{$book['id']}", novalidate)
                =csrf()
                =methodField('PUT')
                .cq-fields.cq-fields--2
                    div
                        label(for='title') * Title
                        input#title.form-control(type='text', name='title', value=$form['title'], maxlength='200')
                    div
                        label(for='author_id') * Author
                        select#author_id.form-select(name='author_id')
                            each $a in $authors
                                option(value=$a['id'], selected=$a['id'] == $form['author_id'])= $a['name']
                    div
                        label(for='published_year') * Year
                        input#published_year.form-control(type='number', name='published_year', value=$form['published_year'])
                    div
                        label(for='summary') Summary
                        input#summary.form-control(type='text', name='summary', value=$form['summary'], maxlength='2000')
                button.btn.btn-primary.cq-submit(type='submit') Save changes

            if $errors
                p.cq-error(role='alert')= implode(' ', $errors)

            .cq-foot
                a(href="{$home}books") All books
```
- `$found` is what `get_book` returned: the book and its author. The four `-` lines at the top are PHP: they name
  `$book` and `$author`, and set `$form` (the values of the form) and `$errors` when the controller of step 6 did not.
- The header uses `$book` (what is saved); the form uses `$form` (what was typed, after a refusal).
- `=csrf()` and `=methodField('PUT')`: the two hidden fields of the concepts above.
- `$book['summary'] ?: 'No summary yet.'`: the summary, or this text when it is empty.
- No PHP class was needed to show this page: `Route::page` called the capabilities and rendered the view.

### Step 6 - The edit form: a controller

Saving the form is logic of its own: on success, go back to the page; on a refusal, show the page again with what
was typed and the messages. That is a job for a controller. Create the folder `application/controllers/Bookshelf` and:

**File `application/controllers/Bookshelf/BookController.php`** (saves with update_book):

```php
<?php

namespace Bookshelf;

use Caligrafy\Controller;
use Caligrafy\ServiceError;

// The edit form of the book page (PUT /books/{id}). Showing a page is Route::page's job; saving a form, then
// redirecting or showing the page again with the messages, is logic of its own: a controller. It only calls capabilities.
class BookController extends Controller
{
    // PUT /books/{id}: the edit form of the page is sent here
    public function update()
    {
        try {
            $book = $this->call('update_book');   // the inputs are {id} and the fields of the form
            redirect('/books/' . $book['id']);
            exit;
        } catch (ServiceError $e) {
            if ($e->kind !== 'invalid') {
                http_response_code($e->status());
                return view('Bookshelf/notfound', array('message' => $e->getMessage()));
            }
            // show the page again: the form keeps what was typed, with a message per field
            http_response_code(422);
            $found = $this->call('get_book');
            return view('Bookshelf/book', array(
                'found' => $found,
                'authors' => $this->call('list_authors', array()),
                'form' => array_merge($found['book'], $this->request->parameters),
                'errors' => $e->fields
            ));
        }
    }
}
```
- `namespace Bookshelf;`: controllers live in a namespace that matches their folder. That is why the route says
  `'Bookshelf\\BookController@update'` (class, then `@`, then the action).
- `update()`: `$this->call('update_book')` gets `{id}` and the fields of the form. When it works, `redirect()` sends
  the browser to the page of the book, which loads it with GET (so *Reload* does not send the form again); `exit`
  stops right after. The address uses `$book['id']`, the id that update_book returned.
- When the inputs are invalid, the same view is shown with status **422**: `found` and `authors` from the
  capabilities, `form` with what was typed (`$this->request->parameters`), and `errors`, one message per field
  (`$e->fields`). Other errors (`kind` not `invalid`, such as 404) show the Not found page with the message.
- No rule is written here: the controller only calls capabilities and chooses what to show.

**File `application/views/Bookshelf/notfound.pug`** (the message of the ServiceError, for the page of a missing book and after a save):

```pug
extends ../default/master/layoutblocks

//- The message of a refused capability ($message): Route::page's notFound for a missing book, or BookController after a save

block content
    main.cq-page
        .cq-card
            .cq-card-head
                h2.cq-title Not found
                p.cq-note= $message
            .cq-foot
                a(href="{$home}books") All books
```
